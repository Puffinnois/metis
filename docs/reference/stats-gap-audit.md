# Stats gap audit

Plan T1703.1, written on 2026-11-23. What statistics basketball publishes that Metis does not hold, and how each could be had. It is a document only: nothing here changes the app. The build parts (T1703.2 to .4) follow the order in section 4, after the manager's review.

**The rule it applies (D53, the manager's decision, written into `decisions.md` with the first build PR).** Metis holds every statistic it can hold honestly, by one of three routes, in this order:

- **(a)** a column already loaded that no metric reads, shown as its publisher's;
- **(b)** a formula over loaded data, stated in the catalogue and in `nba-statistics.md`, tested, and checked against a published figure where one exists, with the tolerance stated (policy 6);
- **(c)** for a model whose maker publishes no formula, Metis's own estimate, named as Metis's and never under the maker's name.

A statistic no route reaches is listed with its reason (**none**). A source outside the dataset's releases is the owner's decision (D6, D31): section 5 names the candidates, and nothing was fetched from one.

## Summary

- **Loaded columns.** The four leagues' files hold 238 source tables and 9,310 source columns. 3,416 are read by the app's code. Of the 5,894 that are not, 1,389 are ranks Metis works out itself, 1,004 are names, colours and logos, 650 are file bookkeeping, 459 are percentages whose parts are stored, and 2,392 are left for a decision. Most of those sit in tables that repeat others (852) or hold standings splits (364); 165 are identity and crosswalk columns, and the other 1,011 are listed with their coverage in Appendix A, and section 1 says which become metrics, which become T1701's attributes, and which stay unread.
- **The reference.** Of `nba-statistics.md`'s 443 entries, **318 are in Metis, 9 partly and 116 not**. Of the 125 not wholly in: 3 by route (a), 43 by (b), 45 by (c), and 34 by no route. Section 2 adds 29 statistics the reference does not list, found on the pages read: 19 by (a), 2 by (b), 6 by (c), 2 by none. **In all, 154 statistics are not wholly in Metis: 22 by (a), 45 by (b), 51 by (c), 36 by none.**
- **Three findings for the manager.** The dataset publishes a release Metis does not load, `nba_current_impact`: SportsDataverse's predictive impact per player as of each week, 2006-07 to 2025-26, about 12 MB. The NBA file is 5.34 GB against D22's 6 GB, and about 240 MB of it is tables no code reads (section 1.4). `nba-data-sources.md` says `nba_stats_lineups` is not loaded, but the real load holds it (869,214 rows, 136 MB, read by nothing).
- **The estimates (T1401).** RAPTOR-style can be built and tested against FiveThirtyEight's free files, once the owner allows them. A DARKO-style estimate can be built and compared with SportsDataverse's BOBAN, already loaded, but not with DARKO itself. EPM-style and LEBRON-style can be built from loaded data, but no free values exist to test them against, so they can only be tested as predictions. RPM, PIPM, DRIP and the NBA's tracking models cannot be built.

## 1. Loaded columns no metric reads

### 1.1 How the trace was done, and how sure it is

The tables and columns are the real four-league load (`~/.cache/metis-dev/gate13c`), listed from `duckdb_tables()` and `duckdb_columns()` with the files opened read-only. A source table is one whose name starts with `src_`; the built tables (`player_game`, `pub_*`, `shot_*` and the rest) are where the app's own columns live, and they are not counted here.

A column counts as read when its name appears as a word in code that reaches its table. The code is every `.ts` file under `src/main` and `src/shared`, the catalogue, the derived and model builders, the `*Reads.ts` files, the identity builders and the links among them. A file reaches a table when:

- it names the table, or the table without its `src_` prefix, or builds the name from a template that matches it (`src_dash_player_tracking_${file}`, `src_dash_lineups_${group}`);
- or, for a WNBA table, it names the NBA's table of the same name: the recipes map one to the other (`WNBA_PLAYS`, `WNBA_PUBLISHED`);
- or it imports a file that names the table, which is how a recipe reaches its builders (`playsRecipe.ts` names `src_nba_pbp`, and `plays.ts`, `splits.ts` and eleven other files import it);
- or a file that names the table imports it, other than the catalogue, `leagues.ts` and `types.ts`. This is how a shared list of columns reaches its builder (`src/shared/stats/lineups.ts` for `derived/lineups.ts`).

`sources.ts` only declares the files, so it does not count. A column also counts as read when a template in a file naming its table builds a name that matches it (`${prefix}_fgm` in the tracking tables). Three groups were found by hand and added: the ten players by slot (`off_player_${i}`, `home_${i}`, `player_${i}` in the play-by-play, possession, lineup and college builders), and the combine's shooting spots, whose names `profile.ts` builds (`${prefix}${key}_${spot}` with `_made` and `_attempt`).

**How sure it is.** An unread column is unread with good confidence: no code that reaches its table names it, and no template there matches it. The errors run the other way. A common name such as `pts`, found in a file that reaches the table, counts as read even when that file reads `pts` from another table. So the unread counts are a floor, and the true number is somewhat higher. Two checks back this up:

- every whole table the trace calls unread is one `nba-data-sources.md` already calls "not read" or a repeat;
- every column found by hand was confirmed in the code.

The scripts are kept with this branch's working files (`.claude/t1703/`, not committed): `tables.mjs`, `trace.mjs`, `classify.mjs`, `coverage.mjs`.

### 1.5 The impact file, column by column

BOBAN is what the owner's word of 2026-11-23 brings in, so the impact file is worth setting out on its own. `src_nba_impact` has 83 columns, of which Metis reads 22. The unread ones:

- the three BOBAN columns, and SportsDataverse's box prior and REML RAPM (section 1.3), which become metrics;
- `*_n`: a sample count beside each model, 100 % filled, which a metric can use as its sample;
- `*_rank` and `*_pct`: the file's rank and percentile of each model, which stay unread because Metis ranks itself;
- names and bookkeeping.

The file has had no `darko_*` columns since the November 2026 load. `pub_player_darko` holds 14,599 rows on the real load, every DARKO value NULL, so `sdv_darko_*` reads blank everywhere. T1703.2 should replace the three `sdv_darko_*` metrics with BOBAN under its own name, or list them as gone. Which of the two is the manager's choice.

## 4. A build order for T1703.2 to .4

The order weighs what a reader gains against what it costs: a rebuild, the file's size against D22's 6 GB (the NBA's is at 5.34 GB), and read time. No PR that adds a metric starts before the manager says T1702.2 has merged; each new metric carries its categories (`src/shared/stats/categories.ts`).

### 4.1 T1703.2: the unread published columns

1. **BOBAN and SportsDataverse's other impact columns** (NBA, WNBA). Read `boban_*`, `*_box_prior` and `*_reml_rapm` into the published impact tables; add the metrics as SportsDataverse's; retire or relabel the three blank `sdv_darko_*` (section 1.5). Cost: a published-recipe bump; the published tables rebuild in seconds; the file grows by about 1 MB. Check: equal to the source column on every row.
2. **Fantasy points and the combined counts** (all four leagues; the published ones in the NBA and WNBA). The published `nba_fantasy_pts`, `wnba_fantasy_pts` and `fp_high_score`, and the formulas: NBA, FanDuel, DraftKings, PRA, PR, PA, RA, stocks, per minute and per game. These are route (b) entries (412 to 419), but they read only existing components and need no rebuild, so they ride with the published ones. Check: the formula against `nba_fantasy_pts` on every player-season, the tolerance stated from the measured gap.
3. **Standings records by situation** (NBA, WNBA). A published table read at the season grain. Small.
4. **The college splits** (NCAA M and W): half-court, unassisted, transition extras, seconds per possession, play flags, unit zones, rating extras. Cost: a rebuild of the college game tables, and new columns in `player_game`, `team_game` and `unit_game`. The college files are 4.31 and 4.09 GB and grow about 0.85 GB a season (D42), so the added size is measured on a copy before the PR, and the columns that hold under 10 % of rows (`stl_trans` 2 %, `ft_pct_trans` 5 %) are left out unless asked for.
5. **The manager's decisions, not built until taken:**
   - loading `nba_current_impact`, a new release within D6 (about 12 MB of Parquet, 20 seasons, one row per player per as-of date);
   - the dashboards' two-, three- and four-man groups (entry 269), which would raise `pub_lineups` from 61,801 to 277,982 NBA rows;
   - dropping `src_nba_lineups`, 136 MB, unread (section 1.4).
   - Rolling windows and distance curves are not recommended.
